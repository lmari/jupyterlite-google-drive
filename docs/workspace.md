# Workspace sidebar: 0.4 alpha 1

Use a Lumino Widget in the existing left shell, not a second file manager. All actions route to existing commands; opening a listed notebook uses its ID from the current explicitly refreshed authorized list, rechecks metadata, and retains the native-editor warning. Render text with DOM textContent (Drive names are untrusted). No new OAuth scope or persistent credentials. Authorization status is a local token lifecycle state, not proof of connectivity. Refresh explicitly; reset list on account change. Show current notebook mode, mounted data aliases and volatile output. Existing menu workflow remains available. Later: trustworthy per-document save status, renewable authorization with verified same account, durable dependency manifests, data list and folders. Browser tests check sidebar visibility without configuration and direct open from the authorized listing, data and output labels in both DriveFS transports.

## Alpha 2: current notebook save state

The adapter exposes observed busy state, original name, writable/loaded state and last acknowledged upload time, without polling Google. The current editor's model dirty flag and document-context save failure signal distinguish a clean loaded snapshot, an in-flight upload, unsaved edits, failure and acknowledged save. No promise of concurrent global synchronization. Local copies are always labeled local, including after explicit remote export. Keep the existing guard that preserves edits made during an upload. Display an explicit error and recovery action for failure. Tests exercise actual browser save, held PATCH, edit during upload, autosave, conflict and local recovery. The legacy Save to original command cannot redirect a native editor, and Save a new copy uses its original name while preserving its original backing target.

## Alpha 3: renew without changing account

Use Drive v3 about.get with fields=user(permissionId), supported under the existing drive.file scope. Verify candidate token before publishing it. Permission ID is kept only in memory. Same-account renewal preserves notebook baselines, mounts, local links and outputs. Missing identity, failed verification or different account rejects the candidate. A 401 invalidates only the exact rejected token; a late response from an earlier token cannot invalidate a new one. No automatic retries of failed writes. Reference: https://developers.google.com/workspace/drive/api/reference/rest/v3/about/get. Real Google account acceptance required.

## Alpha 5.1: notebook dependency manifest

Use a versioned metadata key jupyterlite_google_drive. Only explicit user action records the current session mount list; only explicit restore triggers metadata requests. Reject malformed manifests, traversal, arbitrary URLs, duplicate aliases and more than 20 dependencies. Preflight each ID and metadata, then atomically register aliases; do not overwrite an existing different ID. No authorization grants, data bytes, credentials or account IDs in metadata. File IDs are visible to notebook readers; references resolve current data rather than pinned versions. Fresh browser context test verifies saved manifest and restored Python reads on both transports. Shared mount namespace and Picker reauthorization for inaccessible files remain limitations.

## Alpha 5.2: selective dependencies

Maintain one manifest per notebook. Add a selected mounted alias without changing other recorded references, even if they are not currently mounted. Remove a recorded reference without deleting or unmounting its file. Keep bulk replacement as an explicit advanced action. Compare path AND ID for the sidebar mounted/missing/conflict status. Never silently replace a recorded path with a different ID. Browser test mounts two files, adds both individually, removes one metadata reference, saves, and checks that a new browser restores only the retained file. Shared session mount namespace is unchanged. README now separates native and local-copy workflows and states actual CI evidence.

## Folder browser (beta 8 development)

Connect and choose Open folder. The app searches for an authorized JupyterLite folder directly under My Drive, creates it if none is visible, and lists authorized children by ID. Subfolders can be opened or created; new notebook copies and Python exports go to the current folder. Existing files are not moved. With drive.file, an existing folder or child created outside the app may not be visible until separately authorized; duplicate visible roots are rejected rather than silently selected. Advanced Picker commands remain explicit compatibility paths to existing files outside the workspace. Recovery commands remain usable without authorization. No recursive deletion, rename or general-purpose native file editing is introduced.

Beta 9 separates the folder browser from notebook/data status. Open folder shows only the current path, folder controls and authorized file rows. The advanced menu command Notebook and data status reveals save diagnostics, mounted data, dependencies and recovery controls. Open folder switches back to the file browser.

Beta 10: five-command primary menu. Save current notebook updates native notebooks through the existing guarded context save, updates linked local copies with explicit confirmation, or creates a new copy in the current folder. Editable UTF-8 datafiles use local text-editor copies with session-only remote links and explicit version-guarded uploads. Binary files are not editable through this workflow. Account changes discard links, not local files. Save current datafile is not the same as exporting Python output.

Beta 11: the current folder's regular authorized datafiles are exposed read-only at /drive/<filename> in native notebooks. Each read retrieves remote bytes; duplicate names and reserved paths are excluded. Explicit dependency mounts under /drive/data remain stable when browsing other folders. Editor copies retain the original basename in a new local directory to avoid overwriting existing files.
